# mobileCallReceive

Android 10 이상 스마트폰에서 수신 전화 정보를 같은 LAN의 Windows 앱으로 전달하는 Compose 앱입니다. `applicationId=net.onebell.mcs`와 패키지를 유지하므로 기존 설치 위에 업데이트됩니다.

## 사용

1. Android Studio에서 이 폴더를 열어 debug 빌드를 설치합니다.
2. [Windows 앱](../CallReceiver/README.md)을 실행합니다.
3. Android에 PC의 LAN IPv4, 포트 `18080`, 경로 `/api/call`을 저장합니다. `127.0.0.1`은 휴대폰 자신이므로 실제 스마트폰에서 PC 접속 주소로 사용할 수 없습니다.
4. 테스트 전화 이벤트 전송으로 PC 연결과 팝업을 확인한 뒤 시작을 누르고 Call Screening 역할을 허용합니다.

별도의 PC 연결 테스트 버튼 없이 테스트 전화 이벤트의 POST 응답으로 연결 상태와 응답 시간을 함께 확인합니다. 성공하면 `PC 연결: 성공 · Nms`로 표시하고 실패하면 `실패`로 표시합니다. 별도 health 요청은 보내지 않으며, 응답 시간은 상세 로그 저장과 재요청을 포함한 테스트 작업 전체 소요 시간입니다. PC 접수 확인과 실제 팝업 표시는 별개이므로 팝업도 직접 확인하세요.

설정 저장·입력 오류·권한 요청·테스트 결과는 잠깐 표시되는 Snackbar로 안내합니다. 기존 하단 실행 로그나 마지막 오류 항목은 추가하지 않습니다. 설정·상태·로그 읽기가 일시적으로 실패하면 기존 파일을 유지하고 1.5초 간격으로 다시 읽습니다. 파일 자체가 손상된 경우 기본값으로 복구하고 서비스는 OFF로 둡니다. 이전 설정·로그를 복원하지 못했다는 안내 후 설정을 다시 저장할 수 있습니다.

## 배터리 사용 설정

시작은 설정 검사 → Call Screening 역할 → 연락처·로컬 네트워크 권한 → 배터리 최적화 확인 순서입니다. 역할과 필수 네트워크 권한이 없으면 배터리 단계에 진입하지 않습니다. 연락처 거부는 시작을 막지 않습니다.

설치 후 최초로 시작의 배터리 단계에 도달하면, 별도 이유 설명 없이 Android 배터리 최적화 제외 허용 창을 엽니다. 이미 제외된 앱이면 창을 생략합니다. 최초 확인 여부는 DataStore의 `batteryOptimizationPromptAttempted`에 외부 화면을 열기 전에 저장하므로 거부·취소·업데이트 이후 자동으로 다시 묻지 않습니다. 앱 데이터 삭제·재설치 시 초기화되며 저장소 손상으로 기본값 복구 시에도 기록이 초기화될 수 있습니다. 해당 기록 저장 실패 시 자동 요청을 생략하고 시작 결과에 안내를 함께 표시합니다.

허용 창에서 거부하거나 뒤로 돌아와도 시작은 계속합니다. 반환된 결과 코드 대신 실제 최적화 제외 상태를 다시 확인합니다. 설정 화면을 지원하지 않으면 배터리 최적화 목록, 앱 정보 순서로 대체하며 거부를 이유로 다음 화면을 연속해서 열지 않습니다.

`배터리 사용 설정 열기`로 언제든 다시 요청할 수 있습니다. 이미 제외됐다면 배터리 최적화 목록을 엽니다. 화면의 `배터리 최적화: 제외됨 / 적용 중 / 확인 불가`는 Android 최적화 상태이며 모든 백그라운드 제한이 해제됐다는 뜻은 아닙니다.

삼성 기기에는 `삼성 절전 예외 설정 열기`가 추가됩니다. 앱을 절전·초절전 목록에서 제거하고 절전 예외 목록에 추가하세요. 삼성 공식 연결을 실행할 수 없으면 앱 정보 화면과 수동 경로를 안내합니다. 삼성 목록에 등록됐는지는 Android 최적화 제외 값으로 판단하지 않습니다. [삼성 공식 안내](https://developer.samsung.com/mobile/app-management.html)

화면 회전은 대기 상태를 유지하며 창을 중복 실행하지 않습니다. 설정 대기 중 중지를 누르면 복귀 후 시작하지 않습니다. 프로세스가 종료되면 대기 중 시작은 취소되고 기존 저장 활성 상태는 유지됩니다. 앱 실행·실제 수신·테스트 전송만으로 배터리 설정 창을 자동 실행하지 않습니다.

배터리 설정을 바꿔도 모든 Timeout 원인이 해소된다는 보장은 없습니다. 동일 LAN의 PC 서버를 실행하고 화면 OFF·대기 후 실제 수신 전송을 별도로 확인하세요. [Android 공식 배터리 최적화 안내](https://developer.android.com/training/monitoring-device-state/doze-standby)

변경 구조와 확인 범위는 [배터리 제한 설정 구현·검증](../docs/배터리-제한-설정-구현-검증.md)을 참고하세요.

## 전송 정책

이벤트 JSON은 `schemaVersion`, `eventId`, `phoneNumber`, `receivedAt`, `sentAt`, `isTest`만 포함합니다. device ID, API key와 인증 헤더는 사용하지 않습니다.

수신 전화는 즉시 허용합니다. 연결 실패·타임아웃·소켓 연결 끊김은 최초 요청에 더해 최대 1회 즉시 재요청합니다. connect/read/write/call timeout은 각각 5초이며, 전체 요청 한 번은 최대 5초로 제한됩니다. HTTP 오류(408·429·5xx 포함), 잘못된 JSON·success/eventId 불일치·주소/권한/TLS 오류는 재요청하지 않습니다. 테스트 전화도 같은 정책을 사용합니다.

재요청은 같은 eventId·receivedAt을 유지하며 sentAt만 갱신합니다. 실제 전화는 재요청 전에 서비스 사용 상태를 다시 확인하므로 중지하면 다음 시도를 보내지 않습니다. 이미 서버에 도착한 요청은 취소할 수 없습니다. 최종 실패나 프로세스 종료 후 이벤트를 전송 큐에 보관하거나 재시작 시 보내지 않습니다. 기존 WorkManager 작업과 `call-events.db` 정리는 유지합니다.

## 상세 전송 로그

로그 탭의 카드를 누르면 수신 시각·번호, 대상 URL, 요청 JSON, 응답 상태·본문, 시도별 결과·처리 단계와 원본 오류를 확인할 수 있습니다. `휴대폰 IP → 서버 IP:Port`는 실제 연결 소켓에서 확인한 주소입니다. 연결 전에 실패하면 IP 미확인으로 표시합니다. 로컬 Port와 참고 주소는 수집·표시하지 않습니다. 화면의 시각과 별도 `sentAt` 항목은 한국 시간 `yyyy.MM.dd HH:mm:ss.SSS`로 표시하며 요청 JSON 자체는 실제 전송한 원문을 유지합니다.

상세 화면 마지막의 `복사하기`를 누르면 모든 전송 시도·JSON·오류·잘림 안내를 포함한 전문을 일반 텍스트로 복사합니다. 화면과 복사는 같은 포맷을 사용하며 성공·실패 안내를 표시합니다.

최근 200건을 DataStore에 보관하며 한 이벤트의 두 시도는 같은 로그에 묶습니다. 구형 로그는 기존 요약을 유지하고 상세가 없는 항목을 기록 없음으로 표시합니다. 프로세스가 종료되어 미완료로 남은 로그는 완료 여부 확인 불가로 표시하며 재전송하지 않습니다. 요청 진단은 최대 16KB, 응답 진단은 최대 4KB까지만 저장하고 잘림·불완전 읽기를 표시합니다.

로그·마지막 전송 상태 저장 실패는 실패한 저장소와 별개인 메모리 경고로 안내합니다. HTTP 성공을 실패로 바꾸거나 추가 전송하지 않습니다. 기록 실패 경고가 발생하면 이번 실행의 후속 작업 결과에도 함께 안내하여 전송 성공 메시지에 가려지지 않게 합니다. 이 경고 자체는 저장소 실패 중에도 안내할 수 있도록 메모리에 유지하며, 프로세스 종료 후까지 보존되는 것은 아닙니다.

`PC 접수 확인 성공`은 PC의 success/eventId 응답 확인을 뜻하며 팝업 표시를 보장하지 않습니다. Timeout이어도 PC가 이미 이벤트를 저장했을 수 있습니다. PC 상세 창에서 같은 eventId의 저장·중복 여부와 팝업 상태를 대조하세요. HTTP 서버까지 도달하지 않은 실패는 PC 최근 요청에 나타나지 않을 수 있습니다.

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

APK는 `app\build\outputs\apk\debug\app-debug.apk`에 생성됩니다. 실전화, 화면 OFF, 제조사 절전 정책과 LAN 방화벽은 실제 장비에서 별도로 확인해야 합니다.

설치용 서명 APK는 버전 태그로 자동 생성합니다. 배포 키와 GitHub Secrets 등록, 버전 변경 및 태그 생성 방법은 [GitHub Release 배포 안내](../docs/RELEASE.md)를 따릅니다.
