# mobileCallReceive 사용 안내

Android 10 이상 휴대폰에서 수신 전화번호와 시간을 같은 네트워크의 [Windows 프로그램](../CallReceiver/README.md)으로 전달합니다.

## 처음 사용하기

1. GitHub Release에서 APK를 내려받아 휴대폰에 설치합니다. 설치 과정에서 요청하면 해당 파일을 연 앱의 설치 허용 설정을 확인하세요.
2. PC에서 `CallReceiver.exe`를 실행하고 **서버 설정**의 상태가 **실행 중**인지 확인합니다.
3. 휴대폰과 PC를 같은 네트워크에 연결합니다. 예를 들어 휴대폰은 같은 공유기의 Wi-Fi, PC는 해당 공유기의 유선 또는 Wi-Fi를 사용합니다.
4. 모바일 앱에 PC의 **서버 IP**, **Port**, **API Path**를 입력하고 **저장**을 누릅니다.
5. **테스트 전화 이벤트 전송**을 눌러 PC에 팝업이 나타나는지 확인합니다.
6. **시작**을 누르고 전화 감지 역할과 필요한 권한을 허용합니다.
7. **서비스 사용: ON**을 확인한 뒤 실제 수신 전화가 PC에 표시되는지 확인합니다.

입력 예시:

| 항목 | 예시 |
|---|---|
| 서버 IP | `192.168.0.50` — PC의 현재 주소에 표시된 IP |
| Port | `18080` |
| API Path | `/api/call` |

실제 값은 PC 설정과 일치해야 합니다. 휴대폰에서 `127.0.0.1`은 휴대폰 자신이므로 PC 접속 주소로 사용하지 마세요. 설정을 수정했다면 테스트나 시작 전에 저장하세요.

## 권한과 배터리 설정

- **Call Screening 역할**: 수신 전화 감지에 필요합니다.
- **연락처 권한**: 연락처에 저장된 번호 감지에 필요합니다. 거부해도 시작할 수 있지만 감지가 제한될 수 있습니다.
- **로컬 네트워크 권한**: 요청하는 Android 버전에서는 PC 연결을 위해 허용해야 합니다.
- **배터리 최적화 제외**: 최초 시작 시 시스템 허용 창이 나타날 수 있습니다. 거부해도 시작은 가능하며 **배터리 사용 설정 열기**에서 다시 설정할 수 있습니다.

삼성 기기는 최초 시작 시 절전 예외 목록도 한 번 엽니다. 앱을 절전·초절전 목록에서 제거하고 절전 예외 앱에 직접 추가하세요. 나중에는 **삼성 절전 예외 설정 열기**를 사용합니다. Android의 배터리 최적화 제외와 삼성 절전 예외 목록은 별도 설정입니다.

역할과 권한은 **앱 권한 설정 열기**에서 다시 확인할 수 있습니다. 배터리 설정만으로 모든 연결 오류가 해결되는 것은 아니므로 화면을 끈 상태의 실제 전화도 확인하세요.

## 시작·중지와 테스트

- **시작**: 실제 수신 전화 정보를 PC로 전달합니다. 발신 전화는 전달하지 않습니다.
- **중지**: 새 실제 전화 이벤트의 전송을 중지합니다. Call Screening 역할은 유지되고 일반 전화 수신도 그대로 가능합니다.
- **테스트 전화 이벤트 전송**: PC 연결과 테스트 팝업을 확인합니다. 중지 상태에서도 사용할 수 있습니다.

전화 자체는 차단하거나 무음으로 처리하지 않습니다. 연결 실패·Timeout 등의 통신 오류에는 최대 1회 재요청하고, 최종 실패한 이벤트는 보관하거나 나중에 다시 보내지 않습니다.

## 로그 확인

**로그** 탭에서 최근 전송 기록을 확인하고 항목을 누르면 수신 시각·전화번호·대상 주소·요청 데이터·응답·시도별 결과를 자세히 볼 수 있습니다. 상세 화면 마지막의 **복사하기**로 전문을 복사할 수 있습니다.

최근 200건을 보관하며 표시 시각은 한국 시간입니다. **PC 접수 확인 성공**은 PC의 접수 응답을 확인했다는 뜻이므로 실제 팝업도 확인하세요.

## 전송이 안 될 때

1. PC 서버의 실행 상태와 모바일의 IP·Port·API Path를 확인합니다.
2. 같은 네트워크 연결, Windows 방화벽 허용, PC의 절전·최대 절전 여부를 확인합니다.
3. 테스트는 되지만 화면 OFF나 실제 전화에서 실패하면 앱 권한과 배터리 제한 설정을 확인합니다.
4. 모바일 상세 로그와 PC의 최근 요청을 비교합니다. Timeout이어도 PC가 이미 접수했을 수 있습니다.

배포 방법은 [GitHub Release 안내](../docs/RELEASE.md)를 참고하세요.
